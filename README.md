# 麻将联机（哈尔滨 / 双鸭山）

一个开房即玩的网页麻将：**分享链接就能进房**，人数不够自动补人机，服务端权威判定，断线可重连。
目前内置两套规则预设：**哈尔滨麻将**、**双鸭山麻将**，规则参数化，方便继续扩展其他玩法。

- 线上地址：<http://39.106.36.10/>（分享链接格式：`http://39.106.36.10/?r=房间号`）
- 技术栈：Node.js 20 + Socket.IO + 原生前端（无构建步骤）
- 当前版本：v1.6.0（双玩法规则配置面板、地方规则扩展、传统牌面与移动端交互优化）
- 容量：2 核 2G 单机，20 人左右在线（约 5 桌）无压力

---

## 一、功能

| 功能 | 说明 |
|---|---|
| 开房 / 链接邀请 | 创建房间得到 5 位房间号，复制链接发给朋友，打开自动进房 |
| 座位 / 准备 / 开局 | 4 个座位，空位可坐；房主可加人机、踢人、开局 |
| 人机补位 | 空位加机器人；中途掉线 8 秒后自动托管，重连即恢复 |
| 退出 / 解散房间 | 主动退出会移出房间；有其他真人时座位交给人机，最后一名真人退出立即结束；房主或授权用户可解散 |
| 断线重连 | 身份存在浏览器本地，刷新/断网后自动回到原座位和牌局；房主断线且仍有在线真人时自动转移房主 |
| 自动结束 | 最后一名在线真人断线后保留 30 秒重连时间，超时自动关闭，不再出现纯人机无限续局 |
| 用户管理 | 持久化用户身份与昵称；管理员可查看在线状态、所在房间并实时调整权限 |
| 管理员后台 | 查看用户与房间、解散任意房间、设置创建房间/人机/解散/VIP/管理员权限 |
| 规则预设 | 哈尔滨/双鸭山共用配置面板；支持局数、时间、底分、封顶及分组的有效规则开关，未证实变体标注“待确认” |
| 服务端权威 | 所有吃碰杠胡、番型、结算均在服务端计算，前端只做展示 |
| 手机适配 | 竖屏/横屏自适应，手牌动态缩放，小屏不裁切 |
| 传统牌面 | 42 张完整传统麻将 PNG（万筒条、风箭与花牌），按牌编码复用并随版本缓存 |
| 出牌交互 | 单击选中、同牌辅助高亮、再次单击或按钮出牌，带飞牌、音效与触觉反馈 |
| 报听辅助 | 仅标记实际可听的弃牌，选中后预览听张 |
| 房间设置 | 开局前可切换玩法并配置人数、局数、时间、分数、宝牌/胡牌/计分规则；桌面双栏、手机横向玩法栏 |
| 聊天 | 牌桌聊天 + 快捷短语 |

## 二、规则实现

### 哈尔滨麻将

- 112 张：万/筒/条各 36 + 4 张红中；无风牌、花牌。
- 庄 14 张、闲 13 张；牌墙末张为**宝**（指示牌），报听后可见。
- 默认胡牌条件：**必须开门**（吃/碰/杠过至少一组）、至少两门花色并禁清一色、须有幺九与有刻有顺、最多 3 组副露、必须报听；默认禁止七对与十三幺。
- 可选胡牌规则：站立立听（允许门清并额外计 3 番）、七对、清一色、飘胡、红中不顶大叉、纯夹/死卡、不夹不胡、三七夹与单吊夹。
- 宝：默认未报听玩家看不到宝牌，报听后于下一次摸牌公开；可选暗宝/快宝。自摸到宝可当任意牌，卡当听牌中宝为宝中宝。漏胡、红中满天飞、刮风按对应开关触发特殊自摸结算。
- 计分：平胡 1 番、自摸 2 番、摸宝 3 番、卡当 ×2、宝中宝 12 番、封顶 36；可选经典/传统/高分场倍率 ×1/×2/×4，杠分可即时或延迟结算。
- 点炮：放炮者未听牌时包三家；可选“听后出手炮”也按包三家结算。抢杠胡按点炮结算。

### 双鸭山麻将

- 112 张：万/筒/条 + 4 张红中；**无宝牌**。
- 胡牌须**有幺**（1/9 或红中）；可门清（闷听）、可手把一、可七对、可清一色。
- 牌型：屁胡 1、夹胡 2、飘胡 4、七小对 4（底分）。
- 倍数：自摸 ×2、点炮 ×2、闷听 ×2、杠上开花 ×2、流泪（杠后打出被胡）×2、海底 ×2、手把一 ×2、清一色 ×2、庄家 ×2。
- 杠：明杠 2、暗杠 2、补杠 2，即时结算（明杠由放杠者付，暗/补杠三家付）；可关闭杠分与点炮包三家。
- 手把一为 3 组副露、2 张暗牌，计 ×2；可选本房规“手把一可换牌”，在本次摸牌阶段查看牌墙并换牌一次。
- 点炮包三家；封顶默认 64。

### 房间可配置项

`规则预设`、`局数(1-32)`、`底分(1-10)`、`出牌时间(8-60s)`、`响应时间(5-30s)`、`封顶`、`允许吃`、`一炮多响`、`人数不足补人机`、`公开房间`，以及两套玩法各自分组的宝牌、胡牌与计分选项。配置由服务端白名单归一化，房间快照保存实际生效规则。
规则预设在 `server/rules.js` 的 `RULE_PRESETS` 与 `RULE_OPTION_SCHEMA` 中；缺少统一口径或计分公式存在冲突的地方变体仅展示原因，不提供无效开关。当前版本固定四人对局。

### 用户权限与管理后台

管理员入口默认隐藏：在首页底部版本号上 2 秒内连续点击 7 次，或按 `Ctrl+Shift+A`，再用管理员口令登录。后台支持按昵称或用户标识搜索、查看在线状态和所在房间、解散房间，以及实时修改以下权限：

- `canCreateRooms`：创建房间。
- `canUseBots`：添加人机；关闭后房主不能自动补齐机器人。
- `canDissolveRooms`：以非房主身份解散房间。
- `vip`：牌桌与等待席 VIP 标识。
- `admin`：管理员标识；撤销后该用户已登录的后台会话也会立即失效。

管理员不能取消自己的管理员权限。权限变更通过 Socket.IO 实时推送到该用户的所有连接，并持久化到服务器。

### 已知简化（后续可补）

- 哈尔滨：摸大宝/摸小宝区分、听吃听碰、荒庄查叫、天胡地胡。
- 双鸭山：“大闷”六分类、特胡、缺幺胡幺等地方细则。
- 无花牌、买马、战绩持久化（服务器重启后房间清空）。

## 三、本地开发

```bash
npm install
npm run dev          # http://127.0.0.1:3000
npm test             # 核心牌型 / 规则 / 机器人对局 / 用户权限 / 房间生命周期测试
npm run test:ui      # 真实浏览器交互、管理后台与移动端布局测试（需要 Chrome）
npm run check        # 前端与服务端语法检查
```

目录：

```
server/
  index.js      HTTP + Socket.IO 入口
  users.js      用户身份、持久化与权限
  rooms.js      房间、座位、对局生命周期
  game.js       单局状态机（发牌/摸打/吃碰杠胡/宝牌/结算）
  rules.js      规则预设与胡牌约束
  scoring.js    哈尔滨番制 / 双鸭山倍数制
  mahjong.js    牌、胡牌、向听、听牌、分解
  bot.js        人机 AI（向听 + 牌效启发式）

  index.html    单页应用
  js/app.js     客户端逻辑与渲染
  css/style.css 牌桌样式（响应式）
test/           node:test 测试
```

## 四、部署与运维（39.106.36.10）

| 项 | 值 |
|---|---|
| 系统 | CentOS 8.2（2 核 2G） |
| Node | `/opt/node`（v20.19.0） |
| 应用 | `/opt/majiang` |
| 进程 | systemd `majiang.service`，监听 80 |
| 日志 | `journalctl -u majiang -f` |

常用命令：

```bash
systemctl status majiang
systemctl restart majiang
journalctl -u majiang -n 100 --no-pager
curl -s http://127.0.0.1/healthz
```

更新流程：本地执行 `.\deploy.ps1`（打包 → 上传 → 切换目录 → 重启 → 版本健康检查）。部署脚本会保留 `/opt/majiang-backup-时间戳`，健康检查失败时自动恢复上一版本；服务器重启会清空当前房间，请避免在牌局进行中更新。部署通过 systemd drop-in 设置 `NODE_OPTIONS=--max-old-space-size=1280`，并在 `ExecStart` 直接启用 `--optimize-for-size`（Node 不允许把该参数放入 `NODE_OPTIONS`），为系统和其他进程保留内存；如首次设置或轮换管理员口令，可执行 `.\deploy.ps1 -AdminPassword "新口令"`，脚本仅临时传输，不写入发布包或仓库。

用户数据保存在 `/opt/majiang/data/users.json`，管理员口令保存在 `/opt/majiang/data/admin-secret.txt`，部署时会自动保留；首次部署若没有口令文件，会生成随机强口令。可执行 `cat /opt/majiang/data/admin-secret.txt` 获取管理员登录口令，`users.json` 仅保存身份凭证的 SHA-256 哈希，不保存明文。数据目录权限为 `700`，文件权限为 `600`。也可通过 `MAJIANG_DATA_DIR` 和 `ADMIN_TOKEN` 环境变量指定位置或口令。

静态 CSS/JS 按版本缓存，HTML 每次校验；HTTP 响应启用 gzip 压缩，`/healthz` 返回当前版本用于发布校验。

> 端口 80 已在阿里云安全组放通；如需域名/HTTPS，建议前置 Nginx 并申请证书。

## 五、协议摘要

客户端 → 服务端：`hello`、`room:create`、`room:join`、`room:sit`、`room:stand`、`room:ready`、`room:start`、`room:addBot`、`room:removeSeat`、`room:leave`、`room:dissolve`、`room:config`、`room:continue`、`room:restart`、`game:act`、`chat`、`admin:login`、`admin:state`、`admin:setFeatures`、`admin:dissolveRoom`。
服务端 → 客户端：`hello:ok`、`identity:reset`、`room:created`、`room:joined`、`room:state`（个性化快照）、`room:left`、`room:closed`、`user:features`、`admin:ok`、`admin:state`、`admin:revoked`、`error:msg`。
`game:act` 的动作：`discard`、`chi`、`peng`、`gang`、`angang`、`bugang`、`hu`、`ting`、`tingHint`、`revealDraw`、`swapDraw`、`pass`。普通对局不主动遍历听牌，仅玩家点击听牌提示后计算；有“换牌”权限的用户可在本次摸牌阶段双击牌墙数量，查看剩余牌的种类和数量并替换摸牌，每次摸牌限一次，服务端校验且不返回牌墙顺序。

管理员入口默认隐藏：在首页底部版本号上 2 秒内连续点击 7 次，或按 `Ctrl+Shift+A`，再用管理员口令登录。管理员可开关创建房间、人机、解散房间、VIP、换牌和管理员权限；权限变更会同步到在线用户与正在进行的牌局。
