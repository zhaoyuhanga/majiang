# 麻将联机（哈尔滨 / 双鸭山）

一个开房即玩的网页麻将：**分享链接就能进房**，人数不够自动补人机，服务端权威判定，断线可重连。
目前内置两套规则预设：**哈尔滨麻将**、**双鸭山麻将**，规则参数化，方便继续扩展其他玩法。

- 线上地址：<http://39.106.36.10/>（分享链接格式：`http://39.106.36.10/?r=房间号`）
- 技术栈：Node.js 20 + Socket.IO + 原生前端（无构建步骤）
- 容量：2 核 2G 单机，20 人左右在线（约 5 桌）无压力

---

## 一、功能

| 功能 | 说明 |
|---|---|
| 开房 / 链接邀请 | 创建房间得到 5 位房间号，复制链接发给朋友，打开自动进房 |
| 座位 / 准备 / 开局 | 4 个座位，空位可坐；房主可加人机、踢人、开局 |
| 人机补位 | 空位加机器人；中途掉线 8 秒后自动托管，重连即恢复 |
| 断线重连 | 身份存在浏览器本地，刷新/断网后自动回到原座位和牌局 |
| 规则预设 | 哈尔滨麻将、双鸭山麻将；支持房间级开关（吃牌、一炮多响、封顶、底分、局数、出牌时间） |
| 服务端权威 | 所有吃碰杠胡、番型、结算均在服务端计算，前端只做展示 |
| 手机适配 | 竖屏/横屏自适应，牌面按屏幕缩放 |
| 聊天 | 牌桌聊天 + 快捷短语 |

## 二、规则实现

### 哈尔滨麻将

- 112 张：万/筒/条各 36 + 4 张红中；无风牌、花牌。
- 庄 14 张、闲 13 张；牌墙末张为**宝**（指示牌），报听后可见。
- 胡牌条件：
  - **必须开门**（吃/碰/杠过至少一组），不能门清；
  - 至少两门花色，**禁清一色**；
  - 牌型须**有幺九**（红中可代）、**有刻有顺**（全顺时按“对倒”特例放行）；
  - 不允许手把一（最多 3 组副露）；
  - **必须报听**，报听后手牌锁定、摸牌自动打出；不能七对、十三幺。
- 宝：听牌后自摸到宝可当任意牌（摸宝 3 番）；卡当听牌中宝为**宝中宝 12 番**；牌河/副露中出现 3 张宝自动**换宝**。
- 计分：平胡 1 番、自摸 2 番、摸宝 3 番、卡当 ×2、宝中宝 12 番、封顶 36；杠不计分，杠上开花按自摸。
- 点炮：放炮者未听牌时**包三家**（付三家份额）；无宝牌以外的加番。
- 抢杠胡按自摸结算。

### 双鸭山麻将

- 112 张：万/筒/条 + 4 张红中；**无宝牌**。
- 胡牌须**有幺**（1/9 或红中）；可门清（闷听）、可手把一、可七对、可清一色。
- 牌型：屁胡 1、夹胡 2、飘胡 4、七小对 4（底分）。
- 倍数：自摸 ×2、点炮 ×2、闷听 ×2、杠上开花 ×2、流泪（杠后打出被胡）×2、海底 ×2、手把一 ×2、清一色 ×2、庄家 ×2。
- 杠：明杠 2、暗杠 2、补杠 2，即时结算（明杠由放杠者付，暗/补杠三家付）。
- 点炮包三家；封顶默认 64。

### 房间可配置项

`规则预设`、`局数(1-32)`、`底分(1-10)`、`出牌时间(8-60s)`、`响应时间(5-30s)`、`封顶`、`允许吃`、`一炮多响`、`人数不足补人机`、`公开房间`。
规则预设在 `server/rules.js` 的 `RULE_PRESETS` 中，新增玩法只需增加一份配置（牌墙、胡牌约束、番种/倍数）。

### 已知简化（后续可补）

- 哈尔滨：摸大宝/摸小宝区分、听吃听碰、荒庄查叫、天胡地胡。
- 双鸭山：“大闷”六分类、特胡、缺幺胡幺等地方细则。
- 无花牌、买马、战绩持久化（服务器重启后房间清空）。

## 三、本地开发

```bash
npm install
npm run dev          # http://127.0.0.1:3000
npm test             # 核心牌型 / 规则 / 机器人对局测试
```

目录：

```
server/
  index.js      HTTP + Socket.IO 入口
  rooms.js      房间、座位、对局生命周期
  game.js       单局状态机（发牌/摸打/吃碰杠胡/宝牌/结算）
  rules.js      规则预设与胡牌约束
  scoring.js    哈尔滨番制 / 双鸭山倍数制
  mahjong.js    牌、胡牌、向听、听牌、分解
  bot.js        人机 AI（向听 + 牌效启发式）
public/
  index.html    单页应用
  js/app.js     客户端逻辑与渲染
  css/style.css 牌桌样式（响应式）
test/           node:test 测试
```

## 四、部署与运维（39.106.36.10）

| 项 | 值 |
|---|---|
| 系统 | CentOS 8.2（2 核 2G） |
| Node | `/opt/node`（v20.19.0） |
| 应用 | `/opt/majiang` |
| 进程 | systemd `majiang.service`，监听 80 |
| 日志 | `journalctl -u majiang -f` |

常用命令：

```bash
systemctl status majiang
systemctl restart majiang
journalctl -u majiang -n 100 --no-pager
curl -s http://127.0.0.1/healthz
```

更新流程：本地执行 `.\deploy.ps1`（打包 → pscp 上传 → 解压 → 重启），或手动：

```powershell
tar -czf majiang.tar.gz -C .deploy majiang
pscp -pw <密码> majiang.tar.gz root@39.106.36.10:/tmp/
plink -pw <密码> root@39.106.36.10 "rm -rf /opt/majiang && tar -xzf /tmp/majiang.tar.gz -C /opt && systemctl restart majiang"
```

> 端口 80 已在阿里云安全组放通；如需域名/HTTPS，建议前置 Nginx 并申请证书。

## 五、协议摘要

客户端 → 服务端：`hello`、`room:create`、`room:join`、`room:sit`、`room:stand`、`room:ready`、`room:start`、`room:addBot`、`room:removeSeat`、`room:config`、`room:continue`、`room:restart`、`game:act`、`chat`。
服务端 → 客户端：`hello:ok`、`room:created`、`room:joined`、`room:state`（个性化快照）、`error:msg`。
`game:act` 的动作：`discard`、`chi`、`peng`、`gang`、`angang`、`bugang`、`hu`、`ting`、`pass`。
